1. Executive Summary

Safepoint Billing's Follow-Up subsystem uses the standard Duck Creek FollowUp Manager pattern:

  • One dispatch manuscript — Carrier_Billing_Events_FollowUp_Manager_1_0_0_0 (inherited="Billing_Events_FollowUp_Manager_1_0_0_0") — resolves calls into five processor types (PCN, REIN, LTCH, RMDR, COL) across three flow types (Evaluate, Execute, Generate) via its ProcessorsConfiguration table (tableType="local" override="1").
  • No Duck Creek Workflow-engine (BPM/state machine) artifact drives any follow-up processing. Carrier_Billing_Workflow.xml has an empty <model/>.
  • All orchestration is manuscript-rule chaining + the ScheduledActivity status machine (P → I → C/X/F) + the .NET services DuckCreek.BillingFollowUpObj.dll and DuckCreek.BillingMonitoring.dll.
Critical finding #1 — LTCH and RMDR are silently disabled at the carrier layer. The carrier ProcessorsConfiguration table (override="1") routes all three flow rows for LTCH and RMDR to no-op fields: data.SF_DisableLTCH (<value idref="False"/>) and data.SF_DisableRMDR (<value idref="False"/>). Confirmed by reading both stub manuscripts.
Critical finding #2 — Reminder Notice base Execute is itself a stub. Even if the carrier dispatch were fixed, Base_ExecuteActivities_WorkingData.Execute_ReminderNoticeProcessing guards <value idref="True"/> under an <if> whose <condition idref="RaiseError_WorkFields.RaiseError_ReminderNoticeNotImplemented"/> fires the error. Two-layer fix required.
Critical finding #3 — PCN, Reinstate, Internal-Collections are fully wired. Confirmed real target fields in dispatch and full method bodies in the rule manuscripts.
Critical finding #4 — Business rules are 100% company-agnostic. No ProcessingOrgUnitCode-keyed branch appears in any timing, tolerance, cadence, plan-code, or threshold table. The only genuine per-company business-rule variance is the AOI/mortgagee copy-distribution filter for NOC / NOL / NOW: SFP = 10 interest types; CIC / MIE = PremiumFinance only.
Critical finding #5 — Billing-initiated Policy transactions bypass Policy UI. Notice of Lapse (Carrier_Billing_Events_NoticeOfLapse_Rules_1_0_0_0) and Equity-Based Cancellation (Carrier_Billing_Events_Cancellation_DueToEquity_1_0_0_0) invoke TransACT.startTransactionRq code="Cancel" reason nonPay via Send.postRq with policyInterface_DCT.url/username/password web-config settings. No explicit onFailure handler at the TransACT node itself.
Critical finding #6 — No named batch jobs for any follow-up type. Only BatchScript_RetryRequests (generic async retry) exists in Billing/BatchScripts/. All notice timing is done by the Billing Monitor Windows service (DuckCreek.BillingMonitoring.dll) — its schedule is outside the manuscript tree.

3. Framework Overview (ManuScript Follow-Up Engine)

Duck Creek's Billing Follow-Up engine is a table-driven dispatcher running inside the standard ManuScript rules runtime. The engine is invoked from the Policy-to-Billing event bridge:

Billing/Shared/BillingConfig.xml
  <Event name="Billing_ScheduleFollowUpActivitiesEvent"
         manuscript="Carrier_Billing_Events_Account_Actions_1_0_0_0"
         field="ScheduleFollowUpActivitiesEvent.Value"
         transactions="*" />

Each event call flows into Carrier_Billing_Events_FollowUp_Manager_1_0_0_0, which discovers the target field via a local lookup table:

<table id="ProcessorsConfiguration" tableType="local" separator="," override="1">
  <fields>
    <field type="int" name="FieldId" />
    <field type="int" name="ManuScriptVersionId" />
    <field type="int" name="OrderId" />
    <field type="int" name="ProcessingLevel" />
  </fields>
  <rowKeys name="ProcessorType" type="string" find="eq">
    <key value="PCN" />  <key value="REIN" /> <key value="LTCH" />
    <key value="RMDR" /> <key value="COL" />
  </rowKeys>
  <rowKeys name="FlowType" type="string" find="eq">
    <key value="Evaluate" /> <key value="Execute" /> <key value="Generate" />
  </rowKeys>
</table>

Key framework concepts:

  • Field kinds. <public> (path-bound, session-visible), <private> (in-memory), <request verb="…"> (external service call), <lookup tableRef="…">, <iterator>, <affects><reference idref="…" effect="preEffect|postEffect|setValue"/> (data-flow graph).
  • Inheritance semantics. <properties inherited="ParentManuscriptID">; carrier overlays with override="1" silently replace a same-id field/table wholesale, otherwise contents are additive.
  • OverrideBaseRules / AddAdditionalRules gates. Standard carrier-overlay idiom — always inspect both booleans before assuming a carrier override is active.
  • Verb-based service calls. All external interactions use <request verb="X.Y">. Resolved via Billing/Shared/BillingRequestMap.xml to a .NET assembly.
  • Error propagation. <onFailure idref="RaiseError_WorkFields.Xxx">; empty <onFailure value=""/> means silent swallow.

5. High-Level Notice Lifecycle

Narrative flow (13 steps)

  1. Trigger — Invoice generation (FollowUpParameters.CalledFrom="Invoice"), payment/credit/debit posting, due-date change, or manual action (Start, ManualStart, Letter1..3, Task1, Pause, Resume, Restart, ManualStop, PolicyTransfer, Update).
  2. Processor dispatch — Manager reads ProcessorsConfiguration via ManuScript.getFieldDetailRq. Processor.IsEnabled is the first suppression gate.
  3. Eligibility evaluation — PCN: hold codes, PCNAllow, invoice-range match, term membership.
  4. Grace/target-date calculation — Plan-code lookups + non-blackout adjustment via BillingSchedule.getNonBlackoutDateRq.
  5. Notice/action selection — Activity_Generate.ActivityTypeCode ∈ {PCN, RPCN, NOL, NOCF, LTCH, RMDR, COL, ICOL, ECN}.
  6. Suppression validation — Tolerance amt/pct (PCN); balance start/stop (COL); AOI filter (NOC/NOL/NOW); payment-since-last (PCN); SuppressedInvoice; TRFT transfer.
  7. Template selection — Carrier_Forms_Letters_Manuscript picks .doc subdoc by IsSafepoint/IsCajun/IsManatee AND LOB-specific NOC form-number switch.
  8. ScheduledActivity persistence — Status P via ScheduledActivity.addOrUpdateScheduledActivityRq.
  9. Billing Monitor polls — BillingMonitoring.directBillMonitoringRq / agencyBillMonitoringRq → BillingFollowUpObj.executeFollowUpActivityRq.
  10. Notice generation — ManuScript.printFormsRq / Billing.printFormsRq renders PDF to company-specific queue folder (SPIQUEUE_A/E/I/J or LexisNexis_).
  11. Delivery/integration — File drop; OnlineData.addAttachmentRq; (NOC/NOL) Send.httpRq POST to Integration_AgencyMail.URL.
  12. Status update — ScheduledActivity.updateRq → C/X/F.
  13. Follow-up action — Cancellation (TransACT.startTransactionRq code="Cancel") / late-charge (unreachable) / collections start-or-step (BillingCollections.addRq, Task.addRq).

6.3 Cancellation Notices (NOC / NOL / NOW)

Three related notice families, produced from Carrier_Forms_Letters_Manuscript_1_0_0_0.xml:

  • NOC — Notice of Cancellation (Insured + Mortgagee) — driven from PCN activity reaching its legal/mailing-day deadline.
  • NOL — Notice of Lapse — Safepoint-authored, direct-cancels policy from Billing.
  • NOW — Notice of Withdrawal — sent when payment received before cancellation effective date.
NOL direct-cancel path. Carrier_Billing_Events_NoticeOfLapse_Rules_1_0_0_0 (inherits Carrier_Billing_Events_FollowUp_PCN_Rules_1_0_0_0). Execute_CancellationProcess.Value → BaseRules_CancellationProcess.Rules → Requests.CancelPolicyTerm → Send.postRq (policyInterface_DCT.url/username/password) wrapping Session.loginRq + OnlineData.loadPolicyRq + TransACT.startTransactionRq code="Cancel" reason.code="nonPay".
Equity-Cancel two-branch behaviour. Carrier_Billing_Events_Cancellation_DueToEquity_1_0_0_0 (also inherits Carrier PCN Rules): if CurrentDate ≥ EquityDate AND PolicyStatus=ACV → immediate Requests.CancelPolicyTerm. If CurrentDate < EquityDate → Requests.AddScheduledActivityForECN (ActivityTypeCode ECN, UserId admin). Baseline said "immediate only" — correction applied.
NOL scheduled-activity date. NOL_WorkingFields.CalculateNewSchduledActivityDate = CurrentProcessingDate + 1 day, then walked forward to next non-blackout day via BillingSchedule.getNonBlackoutDateRq method="+". Baseline said "immediate" — corrected.

18. Final Findings and Open Items

18.1 Key confirmed findings

  1. PCN, Reinstate, and Internal Collections are fully functional for all three companies. Business rules are 100% company-agnostic.
  2. Late Charges and Reminder Notices are silently disabled at the carrier dispatch layer. RMDR requires two-layer fix.
  3. No Duck Creek Workflow-engine artifact drives any follow-up processing.
  4. No named batch jobs exist for any follow-up notice type.
  5. Custom Safepoint-authored processes introduce Billing-initiated Policy transactions via Send.postRq + TransACT.startTransactionRq — no explicit onFailure at the TransACT node.
  6. The only genuine per-company business-rule variance is AOI/mortgagee copy-distribution filter.

18.2 Areas Needing Business Clarification

  1. Is LTCH & RMDR disablement intentional?
  2. Is narrow AOI distribution for CIC/MIE intentional?
  3. Is MPR ever actually invoked for any live policy?
  4. Do any of the 50 states have a legally mandated minimum notice period different from SPCDN1?
  5. Is the absence of Letter3 template at carrier layer intentional?

18.3 Areas Requiring Code Cleanup

  1. Consolidate duplicate PCN/Cancel/Rescission tables across PCN Rules / NOL Rules / Cancellation-DueToEquity.
  2. Rename SFPC cadence table id or CollectionPlans row key to eliminate collision.
  3. Fix IsManateeNOW path bug.
  4. Standardize the company-discriminator idiom.

19. Overview & Summary (Executive Recap)

19.1 What this document is

A codebase-verified BA/QA-grade technical analysis of the Billing Follow-Up subsystem in Safepoint's Duck Creek Billing configuration, covering the three writing companies Safepoint (SIC / 9999-1), Cajun (CIC / 8888-2) and Manatee (MIE / 7777-3). Every rule, table row, dispatch entry, template file name, verb call, and integration setting cited here was re-read directly from f:\DuckCreek\Billing\ManuScripts\ and f:\DuckCreek\Billing\Shared\ — the input baseline was used only as a reading list.

19.2 Architecture in one paragraph

A single carrier dispatch manuscript (Carrier_Billing_Events_FollowUp_Manager_1_0_0_0, inherited="Billing_Events_FollowUp_Manager_1_0_0_0") drives five processor types — PCN (OrderId 1, Policy), REIN (2, Policy), RMDR (3, Account), LTCH (4, Account), COL (5, Policy) — across three flow types (Evaluate / Execute / Generate). The dispatch is a table lookup (ProcessorsConfiguration, tableType="local" override="1") resolved at runtime via ManuScript.getFieldDetailRq. There is no Duck Creek Workflow-engine artifact anywhere in the pipeline; Carrier_Billing_Workflow.xml is an empty <model/>. Actual scheduling is done by writing ScheduledActivity rows (status P), which the .NET Billing Monitor service (DuckCreek.BillingMonitoring.dll) polls and dispatches into BillingFollowUpObj.executeFollowUpActivityRq. Correspondence is generated by Carrier_Forms_Letters_Manuscript_1_0_0_0.xml which contains the company discriminator (paired _Account.ProcessingOrgUnitCode AND _PolicyTerm.PolicyTermProcessingOrgUnitCode checks) and the AOI/mortgagee copy-distribution filter — the only true company-specific business rule.

19.3 Five headline findings

  1. LTCH & RMDR are silently disabled at the carrier layer. All six dispatch rows point to no-op boolean fields. Base RMDR Execute is also a stub.
  2. PCN, Reinstate, Internal Collections are fully functional and 100% common across the three companies at the business-rule level.
  3. The only genuine per-company business-rule variance is the AOI copy-distribution filter — SFP=10 interest types; CIC/MIE=PremiumFinance only.
  4. Two Billing-initiated Policy transactions bypass Policy-UI transaction start — NOL and Equity-Cancel. Both invoke TransACT Cancel via Send.postRq.
  5. No named batch jobs exist for any follow-up notice type — only BatchScript_RetryRequests. All timing depends on the Billing Monitor Windows service (out-of-scope schedule).
