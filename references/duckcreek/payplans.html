2 · Executive Summary

Safepoint's Duck Creek Billing implementation layers 25 carrier-specific Policy Plans (SP_ACT_P1–SP_ACT_P25) and 10 Account Plans (SP_ACT_A1–SP_ACT_A10) on top of standard Duck Creek base plans (DC_ACT_P*, DC_AGT_P*, DC_CLM_P*). Behavior is driven mostly by ManuScript configuration tables (BillClassDependencies, ValidAccountAndPolicyPlanCombinations, TargetAccountClass, PolicyPlans, ServiceChargePlans), supplemented by a small number of custom SQL stored procedures (Carrier_SP_BIL_*).

The two most consequential pieces of custom logic:

  • Custom Carrier_SP_BIL_AutoPayPlanAssignment — automatically re-plans a policy (e.g. Annual → Semi-Annual/Quarterly) based on the size of the first payment received.
  • Custom The 25-branch UpdatePayPlan endorsement matrix (Carrier_Billing_Events_PolicyTerm_Post_Actions_1_0_0_0.xml) — hard-coded state / escrow / mortgagee / premium-finance rules that switch the Account/Policy Plan when billing-party-relevant endorsements occur.
Headline cross-company finding: Safepoint, Cajun, and Manatee share one identical Pay Plan and Account Plan catalog — a full-codebase search for CJ_ACT/MN_ACT returns zero hits. Every genuine company difference lives in the presentation/routing layer only — document templates, print-queue paths, activity-log narrative prefixes, and payment-gateway carrier labeling — never in down-payment %, installment count, due-date, renewal, or eligibility math. No Line-of-Business gate on Pay Plan eligibility exists anywhere in the Billing layer; LOB only drives which cancellation-notice template renders.

6 · Full Pay / Installment / Restriction Summary
  • Full Pay options: any ANNUAL, 1-installment plan — SP_ACT_P1/P5/P8/P9/P10/P13/P16/P19/P22/P25, DC_ACT_P1/P7, DC_AGT_P1, DC_CLM_P1.
  • Installment counts: Semi-Annual=2, Quarterly=4, 9-Pay=9, 10-Monthly=10, 12-Monthly=12 (via BillClassDependencies.MaxInstallments).
  • Custom schedules: DC_ACT_P9/P10 use fully custom installment tables (Custom1/2Installments + DistributionForCustom1/2Installments) — ⚠ Risk R11 these key off the generic DCT sample code DC_ACT_P9, not the live Safepoint SP_ACT_P9 plan.
  • SP_ACT_P4 (9-Pay) additionally requires Scheduling_PolicyPlanPrivate.IsAdvantagePolicy = true, resolved via Carrier_SP_BIL_getCoverageByPolicyNumber.
  • Validity gate: every SP_ACT_Pxx option is individually validated against the current Account Plan via ValidAccountAndPolicyPlanCombinations — invalid combinations are hidden from the UI, not rejected server-side (Risk R7).

8 · Business Rules Catalog

4.1 · Pay Plan Eligibility

Each SP_ACT_Pxx option on Scheduling_PolicyPlan.PlanCode is gated by SP_ACT_PxxIsValid, which performs a lookup into ValidAccountAndPolicyPlanCombinations keyed by current Account Plan Code + this Policy Plan Code. SP_ACT_P4 additionally requires IsAdvantagePolicy=true. DC_ACT_P9/P10 restricted to accounts with exactly one active PolicyTerm.

4.2 · New Business

On NBUS, PlanCodeDependancies.UpdateDependantPlanValues cascades BillClassDependencies lookups (MaxInstallments, Frequency, CommissionScheme, NBDeposit %, PCNAllow, offsets) and rebuilds custom installments when a custom plan is chosen. PIF discount eligibility recomputed via SetPIFDiscountEligible.

4.3 · Renewal

  1. ChangeRenewalPolicyPlan — fires on RNEW/NBUS when current plan is not SP_ACT_P5, forces the renewal Policy Plan to the "Annual" captioned sibling (fragile caption-string match, not a code lookup).
  2. PostPolicyTermConfigChangeEvent re-fires the same rule, excluding both SP_ACT_P5 and SP_ACT_P9.
  3. Carrier_SP_BIL_UpdateRenewalTermConfig nulls RenewalConfigTemplate/RenewalAccountId/RenewalConfig for P5/P9 specifically — verified idempotent (pure UPDATE...SET...=NULL).
  4. Carrier_SP_BIL_GetPolicyRenewalPlanCode retrieves effective renewal plan code from RenewalConfig (falling back to PolicyTermConfig).

4.4 · Endorsement — the 25-Branch Matrix

UpdatePayPlan.Value (fires only on ENDT) contains ~25 explicit <if> blocks testing PartyInformation.BillToEscrow, FirstMortgageeName, Policy.PolicyStateCode, and current-vs-target plan mismatch. No table drives this — every branch is a literal comparison. Full state/condition/target table lives in Section 9.

4.5 · Cancellation

WriteOffChargeAfterCancellation (FCAN) writes off ISTP receivables not closed/written-off, or suspends payment if an allocation exists. UpdateScheduledActivityDateForCancellation (PCAN) holds Overpayment and schedules RLHD. Small-balance (≤$5) dust auto-write-off on PCAN. ReinstatementFee sets a $50 charge for SC/NC FCAN/PCAN when NonPayCancelReinstateIndicator is true.

4.6 · Reinstatement

ReverseWriteOffAfterReinstate (REIN) reverses previously written-off ISTP. ExecuteReinDueToNoticeOfLapse is an automated, non-user-initiated Reinstatement. Verified conditions: policy Flat Cancelled/FC and NoticeOfLapse.NOL=1 and day-diff between processing date and invoice due date ≤ 15 days and invoice total ≤ suspense on account → system logs in as a service account and calls TransACT.startTransactionRq code="Reinstate" automatically. Confirmed duplicated verbatim across Carrier_Billing_Events_Integration_1_0_0_0.xml, Carrier_Billing_Events_BatchPayment_1_0_0_0.xml, and Carrier_Billing_Events_Payment_Actions_1_0_0_0.xml.

4.7 · Down Payment Calculation

Static: BillClassDependencies.NBDeposit % applied against Premium. Dynamic formulas from Carrier_SP_BIL_AutoPayPlanAssignment are in Section 10.

4.8 · Installment Calculation

MaxNumberOfInstallments ← BillClassDependencies.MaxInstallments. Custom plans build from CustomInstallmentMapping → Custom1/2Installments × DistributionForCustom1/2Installments. InstallmentCount never exceeds MaxNumberInstallments.

4.9 · Due Date Calculation

NewBusinessEarliestBillOffset/RNEarlyInvOffset/LastDueDayOffset ← BillClassDependencies (default 0 for Safepoint plans). Service-charge due-day banding maps Frequency × days-since-effective-date to a due-day offset.

11 · Policy → Billing Flow (Endorsement Plan-Switch Sequence)

Pay Plan Selection Paths

  • Policy side (initial): DCT_ProductBase.xml's PolicyInput.PayPlan — populated by user on Policy application/quote screen.
  • Policy side (endorsement override): SafePoint_Party_Update_2_1_0.xml's PartyInformation.SetAccountPlanCode/SetPolicyPlanCode — overrides pay plan on Party endorsement commit.
  • Billing side (admin selection): Scheduling_PolicyPlan.PlanCode on "Term Plan Setup"/"Renewal Plan Setup" pages.
  • Billing side (system-automated): Carrier_SP_BIL_AutoPayPlanAssignment — reassigns without UI interaction.

Storage & Transmission

Storage: Compressed XML — DC_BIL_PolicyTermData.PolicyTermConfig containing /PolicyTermConfig/Scheduling/@PlanCode, read via cast(decompress(PolicyTermConfig) as xml).value(...) in every stored procedure. Renewal variant in RenewalConfig/RenewalConfigTemplate. History in DC_BIL_PolicyTermHistory/DataHistory.

Transmission: BillingRequests.BillingIntegrationBuildMessageRequest (Local or Remote, gated by DCTBillingIsRemote) → _BillingWorkingDoc.Populate_PayPlans builds <PayPlans><PayPlan Code PlanDesc BillMethod AccountPlanCode PolicyPlanCode/></PayPlans>. Schema-confirmed in RRBillingSchema.xsd.
